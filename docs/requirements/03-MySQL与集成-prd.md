# 分布式任务编排与执行平台｜MySQL 数据与集成需求

补跑批次保存所选逻辑时刻、DAG 版本及基线运行。组织、定义版本和逻辑触发键去重；派生重跑通过父运行号保留谱系，避免与正常计划混淆。

## 数据归属

每个部署拥有独立的 MySQL 8.4 InnoDB 业务库。组织边界进入授权、唯一性和关联校验。长文件可按内容摘要保存在本地文件存储或对象存储，MySQL 持有来源、版本、访问关系和处理结果。缓存和搜索副本可由主记录重建。

## 核心实体与重要属性

| 业务域 | 实体及字段语义标识 | 约束与用途 |
|---|---|---|
| 工作流定义 | dag(workspace,key), dag_version(dag,rev,digest), edge(rev,from_node,to_node) | 可视图与声明式文件互相映射，验证无环、引用存在、输入类型和节点超时。发布生成不可变版本。 |
| 触发与补跑 | schedule(dag,tz,misfire), run(dag_rev,logical_at,trigger_key,state) | 手工、定时及外部触发共享逻辑运行身份。计划声明时区、错过时补跑或跳过、并发上限，补跑前预览时间窗。 |
| 依赖就绪 | node_run(run,node_key,state,input_ref), edge_result(run,edge,outcome) | 按节点依赖成功、全部结束或显式分支决定就绪。跳过和失败分别传播，详情页说明哪条边阻塞。 |
| 租约与配额 | lease(node_run,epoch,worker,until_at), pool(workspace,queue,slots) | Worker 只领取授权队列，心跳延长同一代数。租约期满重派并增加代数，资源配额按组织和队列约束。 |
| 重试与取消 | attempt(node_run,ordinal,operation_key,result), cancel_request(run,deadline) | 按任务类别区分可重试结果。取消阻止新节点启动并通知在跑节点，过宽限期标为超时取消。外部动作使用固定业务操作号。 |
| 重跑与诊断 | rerun(parent_run,selection,new_run), artifact(attempt,kind,checksum) | 提供任务时间线、依赖等待时间、队列时长与日志片段。部分重跑需选择失败节点及受影响后继，创建单独运行并列来源。 |

## 身份、索引与事务边界

- 业务身份按组织＋定义＋逻辑触发键，节点执行身份为运行＋节点＋尝试号确定。重试带相同身份但不同内容时返回冲突并保留两次请求摘要。
- 领取节点与扣减可用槽同事务。结果提交用代数比较并登记后继就绪任务，取消和重试竞争同一版本。
- 主要组合索引按下列访问模式设计：队列、状态、可领取时间；运行、节点；租约截止、代数。大列表按排序字段与主键游标翻页。
- 时间戳保存 UTC，业务时区独立记录。审核、导出和批处理均保存操作者或服务身份、请求编号及输入版本。

## 对外输入和结果

定义发布接口接收 DAG 与输入约束，触发返回运行号；Worker 心跳、续约和完成均传运行、节点和租约代数。

提交类接口返回可查询的资源标识。格式错误返回字段路径，身份无权返回拒绝，版本冲突返回活动版本。批量任务列明逐项结果。调用方失去响应可按原请求键查询或重送。回调和导出只在对应业务结果持久化后可见。

## 恢复与数据生命周期

备份包含主库和被引用文件的清单。恢复到隔离环境后按业务身份、活动版本和摘要校验。过期临时副本先停用再清理，仍被历史凭证或审核记录引用的资料须保留关联和访问限制。组织管理员能够导出保留策略和清理作业结果。

事务与锁语义以 InnoDB 规范为依据。 [MySQL 事务模型](https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-model.html)
