## 验收环境和数据

使用独立 MySQL 实例及可重置样例。准备菱形依赖、间隔计划、宕机恢复、慢任务和非幂等外部调用模拟器。记录版本、输入摘要和机器配置。所有性能数字均为验收目标，实际报告需列出测量结果。

## 故障演练与权限验收

1. 对核心业务使用同一请求标识重送，比较状态、业务记录数与审计时间线。身份口径为组织＋定义＋逻辑触发键，节点执行身份为运行＋节点＋尝试号。
2. 在数据库提交后、客户端取得回执前中断连接，恢复查询并验证同一最终结果。涉及外部系统时同时核查对方回执。
3. 为两个独立组织建立同名对象。分别检查列表、直接详情、导出和后台作业，跨组织返回的数据条数须为零。
4. 从备份恢复到独立环境，重新按对象编号走查 工作流定义 到 重跑与诊断，核对关键数量与引用。

## 容量与观察

1000 个五节点工作流，10 台逻辑 Worker 竞争 20 槽，并发活跃租约不超 20；旧代数提交接受数为零。测试分别记录预热与稳定阶段、并发数、错误分类、p95 和资源占用。告警应区分输入被拒、平台故障与外部依赖延迟。

## 发布验收证据

提交六项业务场景的输入、实际结果、关键记录编号和异常截图或日志。验收人从受限账户再走一次主要流程，核对用户可见结果与 MySQL 业务记录，再签署对应版本。
