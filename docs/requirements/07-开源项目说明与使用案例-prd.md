# 分布式任务编排与执行平台｜开源项目说明与使用案例

**第二个公开案例**　让调度器停机七个逻辑周期后发布新图，选择旧版的三个历史时刻补跑。输出应列出三个唯一触发键、旧图版本及各自产物摘要。再次确认同批后，检查新增运行数为零。

**workflow-runtime** 是面向自托管的 Go 开源项目规划。数据团队需要长期调度依赖任务，在执行节点中断后仍能确认每个节点最终结果。本页是为未来仓库首页与使用手册准备的需求稿，随首次正式发行补入实际版本、安装入口和验证记录。

## 使用场景

定义→发布→触发→就绪→租约执行→依赖解锁→归档。初次体验请准备示例 DAG、固定时钟、任务输入输出和 Worker 故障时间线。

## 公开教程 · 工作流 D4

**准备数据**　A 完成后 B、C 并行，D 等待 B、C 均成功。B 的第一台 Worker 暂停至租约过期，由第二台完成。

**角色与操作**　暂停一台领到任务的 Worker，等待另一台接管，再恢复旧 Worker，比较两次完成回执。

**对照结果**　D 只产生一次就绪转换。旧 Worker 的完成回执为过期，时间线能区分一次逻辑节点和两次执行尝试。

独立复现者应能从工作台或导出报告中找到对应业务编号，沿时间线追查输入、操作与结果。现场演示可使用离线夹具，联网适配器的真实效果和费用另行记录。

## 自托管者需要管理的资源

调度器、两个 Worker、管理站与 MySQL。内置任务读写公开样例，使用独立临时目录模拟外部副作用。

日志内容与任务输入按项目权限读取，超期后保留运行拓扑和结果摘要，历史详情标明已清理的附件。

## 常见问题

**外部动作已经发生但 Worker 失联怎么办？**

按登记的外部业务键查询结果，无去重或查询能力时暂停并要求人工裁决。

## 社区如何参与

项目接受Worker SDK 与任务类型方面的贡献。声明输入输出、取消处理、幂等能力与兼容版本。验收至少包括一次重复完成、租约丢失和外部动作结果未知。报告差异时请附发布版本、最小样例、期望值和实际结果。涉及生产任务脚本、内部调度凭证、业务日志及客户载荷的材料须先移除，必要时改为独立构造的最小样例。
