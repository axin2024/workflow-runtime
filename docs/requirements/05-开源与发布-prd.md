# 分布式任务编排与执行平台｜独立开源发行需求

首个公开发行附调度器、两个可暂停的示例 Worker、MySQL、固定时区及公开样例图。验收人可断开外网复现接管，七天选择性补跑的数据附逻辑时刻与输入摘要。

## 谁能运行和验证

独立仓库建议名为 **workflow-runtime**，主技术方向为 Go。完整发行需允许第三方在自己的机器上安装全部六项业务能力、导入样例、验证结果并自行修改和再部署。基本演示可离线运行，安装依赖和下载发行包单独说明。可选外部服务使用自托管者自己的账户，接通前提供费用和数据流向说明。

## 自托管交付物

调度器、两个 Worker、管理站与 MySQL。内置任务读写公开样例，使用独立临时目录模拟外部副作用。

仓库首页提供简体中文快速开始、英文摘要、依赖版本表、最小资源配置、安装与升级说明、数据目录、备份与恢复流程。快速开始从空环境建立 MySQL、创建初始管理员、导入样例，一直写到拿到第一份可核对的结果。初始化须提示目标环境，重复执行只复用已登记样例。发布说明列出实际验证过的系统、硬件、启动耗时、已知限制和验证版本。

## 公共数据和完整演示

随发行提供示例 DAG、固定时钟、任务输入输出和 Worker 故障时间线。样例清单逐项登记来源、作者、版本、校验摘要及再分发依据。维护者提供期望输出，并解释输入发生变化时哪些结果会改变。

**首次体验**　暂停一台领到任务的 Worker，等待另一台接管，再恢复旧 Worker，比较两次完成回执。

公开包扫描范围包含源码、历史提交、文档、截图、媒体元数据、容器层和样例导出。须排除生产任务脚本、内部调度凭证、业务日志及客户载荷。录制或模拟结果在工作台和报告上明确标识。性能、质量和可用性声明须能定位到公开版本与测试记录。

## 许可与第三方材料

软件许可候选为 Apache-2.0，由项目所有者在公开前确定。获准后在仓库根目录附完整许可文本，标明版权归属，并按所采用依赖的要求保留声明。文档、示例数据、模型及媒体分别列出适用条款。可下载的第三方权重、托管接口和云服务须分别说明获取方式与运行条件。 [Apache License 2.0 原文](https://www.apache.org/licenses/LICENSE-2.0) · [REUSE 文件级标识规范](https://reuse.software/spec-3.3/)

## 社区贡献和维护

优先接受的扩展方向为**Worker SDK 与任务类型**。声明输入输出、取消处理、幂等能力与兼容版本。验收至少包括一次重复完成、租约丢失和外部动作结果未知。

贡献指南提供本地准备、样例回放、兼容性检查和提交评审流程。缺陷报告须说明发行版本、脱敏输入、预期与实际结果。功能建议写明使用者、当前替代办法和验收条件。维护者复核依赖许可、数据迁移、面向用户的行为变化以及文档更新。安全问题通过安全政策中公布的私密渠道处理，修复版随后给出受影响范围与升级说明。

## 版本与发布顺序

1. **需求定稿。** 记录范围、数据约束、开放接口与验收基线。变更写明受影响需求编号、兼容性和替代方案。
2. **开发与验证。** 实现完整产品，在全新安装和前一受支持版本升级两种条件下运行全部业务验收，保留数据库备份与恢复证据。破坏兼容的变更发布迁移指南并提升主版本。
3. **开源发行。** 项目所有者确认许可与公开范围后发布源码、版本标签、变更记录、依赖清单、样例及校验摘要。GitHub 与 Gitee 如同时发布，使用同一提交与发行摘要，明确主反馈入口。
4. **维护。** 公布受支持版本、安全反馈入口及缺陷处理人。新适配器提交公开契约测试，弃用项列出替代入口与移除版本。

## 公开发行验收

独立验收人在无公司账号、无私有项目依赖的环境完成首次体验。随后导出关键结果，与样例答案核对，再恢复一次 MySQL 备份继续查询历史。附开源许可、第三方清单、复现环境、问题反馈入口和自托管限制。勾选记录须对应实际发行版本。
